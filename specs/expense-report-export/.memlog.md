- (note) worked example for README.md: a fictional team specs a month-end export for its expense app over three runs (create, update, rebuild)
- (event) run 1 started: create the spec from the product owner's notes
- (why) at month end, accounting retypes every approved expense into the accounting software by hand; it takes two days and introduces errors
- (capability) CAP-1 a finance user can export the approved expenses of a month as one CSV file to import them into the accounting software; success: the CSV of a test month imports without error, with one row per approved expense
- (capability) CAP-2 the system emails the previous month's CSV to the accounting mailbox on the 1st of each month; success: on the 1st, the accounting mailbox receives the CSV of the previous month
- (constraint) only approved expenses are exported; draft and rejected expenses never appear in an export
- (constraint) only users with the finance role can export
- (non-goal) no direct integration with the accounting software's API; the file is imported by hand
- (assumption) amounts are exported in the currency in which they were approved, without conversion
- (question) which CSV layout (columns, separator, date format) does the accounting software import?
- (event) validation coherence: PASS, CAP-1 and CAP-2 each have an intent and a success, one non-goal recorded
- (event) validation preservation: PASS, every entry in force (why, CAP-1, CAP-2, 2 constraints, 1 non-goal, 1 assumption, 1 question) appears in spec.md
- (event) spec re-derived: first spec.md written; 2 capabilities, 1 open question on the CSV layout
- (event) run 2 started: add accounting's answers to the spec
- (decision by user) answers the CSV layout question: the export is semicolon-separated with the columns date;employee;category;amount;currency and dates as DD/MM/YYYY
- (decision by user) CAP-2 dropped: accounting prefers to download the file themselves, no automatic email
- (capability) CAP-3 a finance user can export a PDF summary of the month's approved expenses for the auditor; success: for a test month, the totals in the PDF equal the sums of the CSV export
- (question) CAP-3: which totals must the PDF summary show: per employee, per category, or both?
- (event) validation coherence: PASS, CAP-1 and CAP-3 each have an intent and a success, one non-goal recorded
- (event) validation preservation: PASS, every entry in force appears in spec.md; CAP-2 and the answered CSV layout question are superseded and left out
- (event) spec re-derived: CAP-2 removed, CAP-3 added, CSV layout moved from Open Questions to Constraints, new open question on the PDF totals
- (event) run 3 started: spec.md deleted, rebuild it from the memlog alone, no new input
- (event) validation coherence: PASS, CAP-1 and CAP-3 each have an intent and a success, one non-goal recorded
- (event) validation preservation: PASS, every entry in force appears in spec.md
- (event) spec re-derived: rebuilt after deletion, identical to the run 2 spec
